# Устранение неисправностей S3-агента

## Агент не регистрируется

**Причина:** Manager недоступен или неправильный URL.

**Решение:**
1. Проверьте `manager.url` в конфиге
2. Проверьте доступность Manager: `curl http://manager:8000/health`
3. Проверьте логи: `tail -f logs/s3_agent.log`

## События не отправляются

**Причина:** Проблемы с аутентификацией или сетью.

**Решение:**
1. Проверьте JWT токен
2. Проверьте сетевые соединения
3. Проверьте буфер:
   `sqlite3 data/buffer/buffer.db "SELECT COUNT(*) FROM events WHERE sent=0"`

## S3 ошибка "AccessDenied"

**Причина:** Неправильные ключи доступа или политики.

**Решение:**
1. Проверьте `S3_ACCESS_KEY` и `S3_SECRET_KEY`
2. Проверьте политики доступа к бакету
3. Проверьте, что бакет существует

## S3 ошибка "SlowDown" / throttling

**Причина:** S3 временно ограничивает запросы.

**Решение:**
1. Подождите — агент автоматически применит паузу (60с) и повторит
2. Убедитесь, что `poll_interval` не слишком мал
3. Уменьшите количество обрабатываемых файлов за опрос (`max_files_per_poll`)

## Буфер переполняется

**Причина:** Manager недоступен длительное время.

**Решение:**
1. Восстановите Manager
2. Увеличьте `buffer.max_events`
3. Уменьшите `s3.poll_interval`

## Высокая загрузка памяти

**Решение:**
1. Уменьшите лимит `get_unsent` (по умолчанию 100)
2. Увеличьте `cleanup_days` для очистки старых событий не требуется —
   очистка настроена автоматически
3. Перезапустите агент

## Экспоненциальная задержка

При непрерывных ошибках (недоступен Manager, ошибки S3) агент увеличивает
паузу между опросами экспоненциально (до `main.max_error_delay`, по умолчанию
300с). При успехе задержка сбрасывается. Это защищает Manager и S3 от
повышенной нагрузки при сбоях.
